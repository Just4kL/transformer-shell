# Исполнение графа — аппрувнуто и реализовано

Статус: **реализовано** (движок `src/runtime.ts`, кнопка в панели,
`Ctrl+Enter`). Ревью пройдено 2026-09-29.
Решения ревьюера:
1. Дописывание в Журнал — персистентно в содержимое (один прогон — одна точка Ctrl+Z).
2. Кнопка запуска только в панели, TopBar не трогаем.
3. Заметка/Текст входы игнорируют (предсказуемый источник).
Родитель: схема связей v3 (`docs/links-schema.md`, `LAYOUT_VERSION = 3`).

## Идея одним абзацем

Граф из блоков и связей становится исполняемым: кнопка «Запустить»
прогоняет значения по связям в топологическом порядке, циклы крутятся
до стабильности или до `settings.cycleLimit`. Каждый вид блока знает,
что делать со входами и что класть на выходы. Интерактив (кнопки
«Действий») работает и без общего запуска — клик сразу эмитит значение.

## Значение «потока»

```ts
interface FlowValue {
  text: string       // полезная нагрузка, всегда строка
  origin: string     // id блока-источника
  tick: number       // такт исполнения, растёт от 0
}
```

Строка — потому что все тела блоков уже текстовые (заметка, текст,
журнал, строки действий). Структуры позже лягут в `text` как JSON —
формат значения не меняем, только договорённость.

## Семантика видов (v1)

| Вид | Входы | Выходы |
|-----|-------|--------|
| Заметка, Текст | игнорируются | собственное содержимое |
| Журнал | каждая строка входа дописывается в содержимое (`← [время] текст`) | своё содержимое (как было) |
| Действия | игнорируются | клик по кнопке эмитит её имя на все выходы + счётчик (как сейчас) |
| Заглушка, свой тип | — | по базовому виду из таблицы |

Почему заметка игнорирует входы: иначе любая связь в заметку молча
переписывала бы пользовательский текст. Источник — предсказуемо,
приёмник явный — только Журнал. Правило простое, сюрпризов нет.

## Прогон

1. Валидация (`validateLinks`): при ошибках прогон не стартует,
   список — в панель. Предупреждения (циклы) — не препятствие.
2. DAG-часть — порядок Кана (детерминированный: сортировка по id).
3. Циклические компоненты — потактово: каждый такт все блоки цикла
   пересчитываются; стабильность (ни одно значение не изменилось) —
   стоп «стабильно»; иначе стоп на `cycleLimit` — предупреждение
   в бейдж и в Журнал (если привязан).
4. Кнопки «Действий» — вне прогона: клик в любой момент эмитит
   значение на выходы блока немедленно (и считается в тактах прогона,
   если он идёт).

## Где живут результаты

- **Значения на портах** — только runtime, эфемерно: отдельный стор
  `useRuntime` (`Map<blockId, Map<portId, FlowValue>>` + статус
  последнего прогона). В файл не пишется, undo не участвует.
- **Дописанные строки Журнала** — это правки содержимого: персистентны
  и отменяемы, как ручное редактирование. Один прогон — одна точка
  истории (а не точка на строку).
- **Статус прогона** («стабильно за N тактов» / «стоп на лимите») —
  эфемерно, показывается в разделе «Связи» панели.

## Управление

- Кнопка «▶ Запустить» в разделе «Связи» панели (там же лимит и проблемы).
- Горячая клавиша — `Ctrl+Enter` (вне полей ввода, по общему правилу).
- TopBar не трогаем: запуск — действие над графом, ему место в панели.

## Что переиспользуется

- `validateLinks` — ворота прогона без изменений.
- `checkpoint` — одна точка на прогон (до старта).
- Бейдж `tb-links` — добавляем состояние «идёт прогон»? Нет:
  прогон синхронный и мгновенный, мигать нечему. Статус — текстом.
- Экспорт PNG — runtime-значения на портах в снимок не попадают
  (рисуем только структуру); дописанное в Журнал — попадает.

## Вне scope (сознательно)

- Асинхронные блоки, задержки, таймеры (всё синхронно, детерминировано).
- Условные ветвления и типы данных строже строки.
- Пошаговый дебаг (точки останова, подсветка активного ребра).
- Сохранение истории прогонов между перезапусками.

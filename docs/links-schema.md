# Схема связей v3 — драфт на ревью

Статус: **черновик**. Код не пишем, пока нет аппрува на этот документ.
Родитель: схема раскладки v2 (`src/layout.ts`, `LAYOUT_VERSION = 2`).

## Решения (ответы заказчика)

1. **Тип данных на портах — универсальный.** Один вид `any` («поток»).
   Следствие: валидация типов отключена целиком; поле `data` в порте
   резервируем со значением `'any'`, чтобы в v4 ввести строгие типы
   без миграции (старые порты прочитаются как `any`).
2. **Циклы разрешены, но с лимитом.** Статика циклы не запрещает —
   только показывает (warning с путём цикла). Лимит живёт в настройках
   (`settings.cycleLimit`), исполнение (позже) обязано его соблюдать.
3. **Связи сквозь категории разрешены.** Связь ссылается на id блоков,
   категория в ссылке не участвует. Следствие для UI: находясь
   в категории A, связь в категорию B рисуем заглушкой-переходом
   (клик — прыжок к блоку). Данные от этого не зависят.

## Сущности

### Port — гнездо на экземпляре блока

```ts
interface Port {
  id: string          // 'p_12', выдаёт общий счётчик seq
  label: string       // подпись, правит пользователь, max 100
  dir: 'in' | 'out'
  data: 'any'         // зарезервировано под строгие типы в v4
}
```

Порты хранятся **на блоке**: `block.ports: Port[]`.
Почему не в типе: у двух блоков одного типа разный набор гнезд —
это нормально для конструктора (один «Журнал» слушает, другой вещает).
Смена вида блока (`changeKind`) порты не трогает.

Стартовый набор: у нового блока портов **нет**. Пользователь добавляет
их из панели свойств («+ вход» / «+ выход»). Пустой блок без портов —
валиден, это обычная панель данных.

### Link — связь

```ts
interface Link {
  id: string          // 'l_7', общий счётчик seq
  from: { block: string; port: string }  // dir обязан быть 'out'
  to: { block: string; port: string }    // dir обязан быть 'in'
  label: string       // подпись на ребре, max 100, может быть пустой
}
```

Связи — плоский список `links: Link[]` на верхнем уровне состояния,
а не внутри блоков. Причины: удаление блока — один проход фильтром;
подсчёт входящих/исходящих — без обхода всех блоков; undo — бесплатно
(снапшоты и так whole-state).

### Settings

```ts
interface LayoutSettings {
  cycleLimit: number  // 1..10000, default 100
}
```

Поле `settings` на верхнем уровне `PersistedState`. Сейчас используется
только валидацией (предупреждение «цикл длиннее лимита»? нет — лимит
про длину, а про число итераций; статика длину не ограничивает).
Исполнение позже: превышение лимита = остановка с ошибкой в Журнал.

## Пример (фрагмент файла)

```json
{
  "version": 3,
  "state": {
    "blocks": [
      { "id": "b1", "kind": "note", "ports": [{ "id": "p1", "label": "выход", "dir": "out", "data": "any" }] },
      { "id": "b2", "kind": "log", "ports": [{ "id": "p2", "label": "вход", "dir": "in", "data": "any" }] }
    ],
    "links": [{ "id": "l1", "from": { "block": "b1", "port": "p1" }, "to": { "block": "b2", "port": "p2" }, "label": "" }],
    "settings": { "cycleLimit": 100 }
  }
}
```

## Валидация (`validateLinks`, чистая функция)

| # | Проверка | Уровень | Реакция |
|---|----------|---------|---------|
| 1 | Конца нет (блок/порт удалён мимо каскада) | error | связь недействительна, UI не рисует, в список проблем |
| 2 | `from` не `out` или `to` не `in` | error | то же |
| 3 | Дубликат (та же пара портов дважды) | error | вторая и далее недействительны |
| 4 | Петля «порт сам в себя» | error | недействительна |
| 5 | Цикл (включая длину 1 — блок сам на себя) | warning | показать путь `b1 → b4 → b1`; исполнение позже считает итерации до `cycleLimit` |
| 6 | Связь в другую категорию | info | рисуем заглушку-переход, не проблему |

Инвариант sanitize: после загрузки ошибок 1–4 быть не может (битое
отбрасывается). Валидация нужна живому редактированию: между удалением
порта и каскадом, при ручной правке файла.

## Миграция

- Файл v2 (и v1): блокам без `ports` → `[]`; `links` → `[]`;
  `settings` → `{ cycleLimit: 100 }`. Всё остальное без изменений.
- Файл v3 в старой программе: отказ как сейчас (версия выше известной).
- `seq` уже сканирует хвостовые цифры любого id (`/(\d+)$/`,
  Фаза А) — префиксы `p_`, `l_` подхватываются автоматически,
  код менять не надо.

## Семантика удалений (каскад)

- Удалить блок → удалить все его связи. Одна точка истории.
- Удалить порт → удалить все связи через него. Одна точка истории.
- Удалить категорию → блоки переезжают (как сейчас), связи целы:
  endpoints — id блоков, категориям они безразличны.
- Удалить тип блока → блоки переходят на базовый вид (как сейчас),
  порты и связи целы: они принадлежат экземплярам, не типу.
- Смена вида блока → порты, связи, содержимое на месте.

## Что переиспользуется без изменений

- **Undo/redo**: снапшоты whole-state — порты, связи, настройки
  отменяются автоматически. Отдельной истории связей нет.
- **Автосейв**: `toPersisted` подхватит новые поля; лимиты —
  `MAX_LINKS = 2000`, порт `label` ≤ 100, связь `label` ≤ 100.
- **Экспорт PNG**: связи рисуются на холсте → попадут в снимок сами.
- **Sanitize-философия**: неизвестное отбрасываем, чужое чиним,
  своё не теряем. Порт с `dir` не `in/out` — дропаем порт и его связи;
  связь с пустым `label` — валидна.

## Вне scope v3 (сознательно)

- Исполнение графа, семантика значений «потока», порядок обхода.
- Подграфы / сворачивание связей в шину.
- Условные порты («если X, то Y»).
- Строгие типы данных (поле `data` их ждёт в v4).

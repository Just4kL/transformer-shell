# Трансформер — оболочка с двойной разметкой

Десктопное окно (Electron + React + TypeScript), в котором вся вёрстка
выравнивается по двум уровням сетки: **маленькие квадраты 8px** и
**большие квадраты 64px**. На этой оболочке дальше собирается сам
трансформер — блоки, кнопки, вывод и управление.

## Запуск

```bash
npm install
npm run dev        # Vite (5273) + Electron
```

Только браузер (для быстрой правки вёрстки):

```bash
npm run dev:renderer
```

Продакшен-сборка:

```bash
npm run build      # dist/ — рендерер, dist-electron/ — процесс Electron
```

## Двойная разметка

Оба уровня сетки привязаны к началу окна, поэтому элементы «стоят» друг
на друге независимо от того, в какой части окна они находятся.

| Величина      | Значение | Роль                                          |
| ------------- | -------- | --------------------------------------------- |
| `UNIT`        | 8px      | маленький квадрат: шаг, толщина, мелкие размеры |
| `MAJOR`       | 64px     | большой квадрат: ритм панелей, полей, полок    |
| `BAR_H`       | 40px     | панель окна (5 маленьких квадратов)            |
| `PAD`         | 64px     | поля рабочего поля (1 большой квадрат)          |
| `RAIL_MIN`    | 128px    | минимальная ширина рельса категорий             |
| `RAIL_MAX`    | 512px    | максимальная ширина рельса                      |
| `BLOCK_MIN`   | 64px     | минимальный блок (1 большой квадрат)            |

Ключевое: ширина рельса всегда кратна большому квадрату, а панель окна
кратна маленькому. Поэтому сетка рабочего поля остаётся в фазе с общей
сеткой окна — `gridOffset()` в `src/grid.ts` возвращает сдвиг начала
паттерна, который это обеспечивает.

### Как это ощущается

- **Перетаскивание** — блок притягивается к маленьким квадратам, а рядом
  с большим — встаёт на крупный ритм (двухступенчатый снап,
  `snapFlexible`). Вспышка зелёной рамкой значит «встал на крупный».
- **Выравнивание по соседям** — грани блока дополнительно притягиваются к
  граням соседних блоков в пределах 5px, и появляются направляющие.
- **Изменение размера** — восемь ручек; тянутая грань округляется,
  противоположная зафиксирована.
- **Прокрутка** тоже держится маленького квадрата, иначе сетка «плывёт».
- `Esc` во время перетаскивания — отмена, блок возвращается на место.

## Структура экрана

```
┌──────────────────────────────────────────────┐
│ панель окна  40px = 5▪   категория · сетка · ⌫│
├────────┬─────────────────────────────────────┤
│ рельс  ║ рабочее поле                        │
│категор.║  ← сетка 8px / 64px                 │
│ 128px  ║  ← блоки на сетке, направляющие      │
│  2◆    ║                                     │
└────────┴───↕ граница тянется курсором ───────┘
```

- **Рельс категорий** слева — минимальная по ширине колонка (2◆ = 128px).
  Граница между рельсом и рабочим полем тянется мышью и
  притягивается к большому квадрату; двойной клик по разделителю
  сворачивает рельс.
- **Рабочее поле** справа — то, где живут блоки, кнопки, управление и вывод.

## Блоки

Правый клик по полю → **Создать блок** → выбрать, что блок будет
показывать. Сразу после создания открывается поле ввода названия.

| Тип                 | Что показывает                     |
| ------------------- | ---------------------------------- |
| **Заметка**         | Markdown, рендерится вживую        |
| **Текст**            | простой текст без разметки         |
| **Журнал / вывод**   | моноширинный поток, только чтение  |
| **Действия**         | кнопки и элементы управления       |
| **Заглушка**         | пустой блок-контейнер              |

Содержимое правится двойным кликом по телу блока.

### Меню блока

Правый клик по шапке или по самому блоку:

- **Назвать блок…** — переименовать
- **Будет показывать** — сменить тип содержимого
- **Перенести в категорию** — переложить блок в другую категорию
- **Свернуть до квадрата** / **Развернуть содержимое**
- **Развернуть на всё поле** / **Вернуть в сетку**
- **Удалить блок**

### Механизм развёртки

Три состояния одного блока:

1. **Обычное** — блок занимает своё место в сетке.
2. **Свёрнутое** — высота ровно один большой квадрат (64px), остаётся
   только шапка. Клик по шеврону или двойной клик по шапке.
3. **Развёрнутое** — блок занимает всё рабочее поле, поля соблюдаются,
   размер округляется вниз по сетке. Кнопка `⤢` в шапке. Габарит до
   развёртки запоминается, поэтому «вернуть в сетку» возвращает блок
   ровно туда же.

## Горячие клавиши

| Клавиша              | Действие                       |
| -------------------- | ------------------------------ |
| `Ctrl+N`             | новый блок-заметка по центру   |
| `G`                  | показать/скрыть двойную разметку |
| `[`                  | свернуть/развернуть рельс      |
| `Esc`                | закрыть меню, отменить перенос |
| `Enter` в поле имени | подтвердить название           |

## Сохранение раскладки

Раскладка переживает перезапуск. Файл:

```
Windows  %APPDATA%\transformer-shell\layout.json
macOS    ~/Library/Application Support/transformer-shell/layout.json
Linux    ~/.config/transformer-shell/layout.json
```

Точный путь виден в подсказке индикатора сохранения в панели окна и
печатается в консоль при старте.

**Запись атомарная:** сначала во временный файл с `fsync`, затем
переименование. Падение посреди сохранения не оставит обрезанный JSON.

**Автосохранение** с отложкой 500 мс — при перетаскивании состояние
меняется каждый кадр, поэтому пишем только когда пользователь успокоился.
Есть потолок в 2,5 с: если изменения длятся дольше, пишем всё равно.
Повторно не пишем, если содержимое не изменилось.

**Файл не доверяется.** Всё, что читается, проходит `sanitize()`
в `src/layout.ts`:

- числа зажимаются в допустимые пределы, координаты округляются к сетке
- неизвестные типы блоков заменяются на безопасный, битые записи выбрасываются
- повторяющиеся и пустые `id` перевыдаются, `seq` подтягивается вперёд,
  чтобы новый блок не столкнулся с существующим
- ссылка на несуществующую категорию заменяется на первую существующую
- файл из более новой версии программы не трогается вовсе
- лимиты: 500 блоков, 200 000 символов содержимого, 8 МБ на файл

### Мост между процессами

`electron/preload.ts` намеренно не даёт рендереру ничего общего назначения:
нет `fetch`, нет файловой системы, нет запуска процессов. Ровно пять
оконных методов и три операции с раскладкой:

| Метод         | Назначение                |
| ------------- | ------------------------- |
| `saveLayout`  | записать состояние        |
| `loadLayout`  | прочитать состояние       |
| `layoutPath`  | узнать путь к файлу       |

Смысл в том, чтобы поверхность, доступная коду интерфейса, нельзя было
расширить по мере роста приложения. Расширять её придётся сознательно.

## Устройство кода

```
electron/
  main.ts              окно без системной рамки, свои кнопки через IPC
  preload.ts           contextBridge → window.transformer (узкая поверхность)
  layoutStore.ts       атомарная запись и чтение файла раскладки
src/
  grid.ts              вся математика двойной разметки
  layout.ts            схема раскладки и sanitize() — файл не доверяем
  persistence.ts       автосохранение с отложкой, загрузка при старте
  store.ts             состояние оболочки: категории, блоки, развёртка
  interaction.ts       эфемерное состояние перетаскивания и направляющие
  blockTypes.ts        реестр типов блоков («что он показывает»)
  hooks/
    useBlockPointer.ts снап, выравнивание по соседям, изменение размера
  components/
    TopBar.tsx         панель окна
    CategoryRail.tsx   рельс категорий + разделитель
    Workspace.tsx      рабочее поле, сетка, контекстное меню
    BlockView.tsx      блок: шапка, ручки изменения размера
    ContextMenu.tsx    вложенное контекстное меню
    blockMenu.ts       содержимое меню блока
    menu.ts            типы и хелперы меню
  blocks/BlockBody.tsx тела блоков
  lib/markdown.tsx     безопасный мини-рендерер Markdown
```

## Ограничения текущего шага

- Типы блоков — заглушки: «Действия» считает нажатия, «Журнал» —
  статичный текст. Это точки подключения будущих механик трансформера.
- Категории не удаляются — только добавляются и переименовываются.
- Нет отмены последнего действия (`Ctrl+Z`) — история правок не ведётся.
